# 基于 Lumos 引导的 D435 主动观察与抓取设计

日期：2026-08-06

状态：设计已由用户确认，等待书面规格复核

## 1. 背景与问题

Lumos/XVisio 鱼眼 RGB 与 Intel RealSense D435 都固定安装在机械臂末端，D435 位于
Lumos 上方。Lumos 的视场更广，能够发现 D435 当前视场外的桌面物体；D435 提供米制深度，
但不能保证在当前末端姿态下看到 Lumos 发现的目标。

现有视觉架构以 Lumos 为唯一主 RGB：RTMDet-Ins 产生实例掩码，DINOv2 与持久身份内存
维持 `identity_id`；D435 depth 经固定外参注册到 Lumos 掩码后产生三维位姿。现有在线服务
已经实现只读双相机 Dry Run，但双相机外参、手眼标定和真实运动闭环尚未通过执行验收，
`robot_execution_enabled` 必须继续保持 `false`。

本设计解决以下问题：Lumos 锁定桌面目标后，在真正抓取前主动调整末端观察姿态，使该目标
进入 D435 的高质量深度区域；获得稳定且可信的三维位置后，再生成抓取预览并等待人工确认。

## 2. 设计结论

采用“预教安全观察位 + 有界深度闭环”的两阶段主动视觉方案：

1. **粗观察阶段**：利用 Lumos 目标射线、已验证桌面平面和当前机器人姿态得到带不确定度的
   桌面粗位置，从一组预教且验证过的安全观察位中选择能够覆盖该区域的观察位。
2. **精观察阶段**：机械臂停稳并确认仍为同一 `identity_id`；D435 获得有效深度后，仅在深度
   质量不足时执行少量、有界的视角微调。目标是让实例主要区域落入 D435 中央高质量区，
   不是追求目标中心与单个主点像素完全重合。
3. **抓取阶段**：连续多帧的身份、深度、标定、机器人姿态和安全证据全部有效后生成抓取预览；
   第一版必须由操作员确认，确认后才允许进入既有抓取授权和执行链。

粗观察阶段不采用任意在线 IK 追踪，也不在缺少深度时向目标自由靠近。预教观察位限制了未知
深度阶段的运动集合；精观察阶段只允许在已经取得有效 D435 深度后进行小范围修正。

## 3. 考虑过的方案

### 3.1 仅使用固定观察位

为桌面不同区域预教若干 D435 观察姿态，按区域依次查看。该方案最容易验证，但可能需要较多
姿态，视场边缘的深度质量也不可控，目标位置变化后适应性较差。

### 3.2 连续图像视觉伺服

机械臂运动时持续根据 Lumos 或 D435 像素误差调整末端。该方案可能更快，但两相机没有共同
硬件触发，移动相机时身份、深度和机器人姿态更易出现时间错配；在当前安全基础上不适合作为
第一版。

### 3.3 预教观察位 + 有界深度闭环（采用）

用预教观察位完成大范围、安全、可验证的粗移动；目标进入 D435 后再进行 stop-and-look 式
小步修正。该方案兼顾鱼眼视场优势、D435 深度质量和真实机械臂安全性。

## 4. 几何原则

### 4.1 坐标链

所有计算必须使用经过内容寻址和独立验证的变换：

```text
D435 depth optical --T_lumos_from_d435--> Lumos optical
Lumos optical      --T_flange_from_lumos--> flange
flange             --T_base_from_flange(t)--> robot base
```

不得使用固定像素偏移将 Lumos 中心换算为 D435 中心。两相机存在物理基线，D435 光轴在
Lumos 图像中的投影随目标距离变化；必须使用完整相机模型、外参和目标深度。

### 4.2 桌面粗位置

目标确认位于固定桌面。粗观察阶段从 Lumos 实例掩码的下部稳健区域生成多条射线，与已验证的
桌面平面求交，并用射线分散程度、掩码大小、鱼眼径向位置和桌面标定误差形成二维不确定区域。
掩码几何中心可用于目标方向显示，但不单独作为桌面接触点。

该粗位置只允许用于选择安全观察位，不能写入 `position_m`、不能通过抓取授权，也不能替代
D435 深度。

### 4.3 观察位覆盖

每个预教观察位保存：

- 六轴关节目标与预期 flange/TCP 位姿；
- D435 内层高质量视锥在桌面上的覆盖多边形；
- Lumos 与 D435 标定 ID；
- 关节限位、TCP 工作区、桌面间隙、线缆和现场禁入区验证结果；
- 从允许起始姿态到该观察位的已验证路径标识。

规划器选择能够完整覆盖目标粗位置不确定区域、移动代价最低且安全证据仍有效的观察位。没有
观察位满足条件时必须中止，并报告 `no_valid_observation_pose`；不得退化为任意笛卡尔运动。

### 4.4 D435 高质量区

D435 的目标条件是实例掩码有足够面积落入配置的中央质量区域，并拥有足够的有效深度点、
合理的深度分布和低位姿不确定度。中央质量区域初始采用图像宽高各自中间 60% 的矩形，最终
数值由本机深度健康测试固化到配置和校准版本中。

第一版深度获取门限为掩码内至少 80 个有效注册点；稳定门限为连续 5 个 stop-and-look 样本
的三维中心相对时间中位数偏差不超过 10 mm，且每轴 MAD 不超过 5 mm。透明、反光或边缘
飞点导致门限不通过时只能报告深度不可用。这些门限可以在独立实测后收紧，不能在运行中自动
放宽。

如果当前观察位已经满足深度质量门限，则不再为了视觉上“更居中”而移动。零额外动作优先于
形式上的中心对齐。

## 5. 系统边界与组件

### 5.1 PerceptionService

保留现有 Lumos RTMDet/DINO/身份记忆与 D435 深度注册职责。它只发布带时间戳、帧号、
`identity_id`、标定 ID、掩码、深度质量和不确定度的不可变观测，不导入 Startouch SDK，
也不发送运动命令。

### 5.2 ActiveViewPlanner

新增纯计算规划器，输入为目标锁、当前机器人姿态、桌面标定、相机标定、观察位目录和安全配置；
输出 `ObservationMoveProposal` 或明确拒绝原因。规划器负责：

- Lumos 射线与桌面平面粗求交；
- 目标不确定区域估计；
- 预教观察位覆盖和代价排序；
- D435 已有深度时的小步精调提案；
- 提案的证据、有效期和配置哈希。

规划器不得执行运动，也不得把没有 D435 支持的桌面粗位置标为可抓取。

### 5.3 ActiveViewSession

事件驱动会话保存一次抓取请求的目标身份和状态。所有相机观测、规划提案、运动完成事件和人工
确认都必须携带同一个不可复用 `session_id`；旧会话的迟到事件不得推进新会话。

### 5.4 RobotCommandGateway

现有 Node proxy/Startouch bridge 仍是唯一能够发送机械臂命令的进程。它只执行通过独立授权
检查的观察位提案，不接受视觉进程直接发送的裸 `move_l` 或关节数组。抓取与主动观察互斥，
任一时刻只能存在一个运动所有者。

### 5.5 ActiveViewAuthorization

运动授权必须重新验证，而不是信任规划器布尔值。至少检查：

- 真实执行总开关和主动观察功能开关均已启用；
- 标定、桌面、观察位和机器人模型哈希一致且已验收；
- 会话、目标身份、提案、机器人当前状态和观测时间均匹配且未过期；
- 机械臂已连接、当前静止、无其他运动或抓取会话；
- 路径已预教/验证，关节限位、步长、速度、工作区和禁入区检查通过；
- 硬件急停与现场人工条件已由操作员在本次实机试验前确认。

任何字段缺失、陈旧或不一致都必须 fail closed。

## 6. 状态机与数据流

```text
IDLE
  -> TARGET_LOCKED
  -> COARSE_VIEW_PLANNED
  -> MOVE_AUTHORIZED
  -> MOVING_TO_VIEW
  -> SETTLING
  -> VERIFYING_IDENTITY
  -> ACQUIRING_DEPTH
  -> [REFINE_VIEW -> MOVE_AUTHORIZED -> ...]  (有界循环)
  -> GRASP_PREVIEW
  -> WAITING_OPERATOR_CONFIRMATION
  -> READY_FOR_EXISTING_GRASP_GATE
```

规则如下：

1. `TARGET_LOCKED` 保存 Lumos `identity_id`、类别、DINO 原型摘要和请求时标定 ID。
2. 运动期间继续显示画面，但任何融合目标都标记为不可操作；运动帧不更新可抓取三维状态。
3. `MOVING_TO_VIEW` 只由与提案关联的 command-complete 事件结束，不能由固定延时推进。
4. 到位后必须等待关节反馈稳定和配置的 settle 时间，再接受新的相机帧。
5. 移动后至少两次高质量 Lumos 观测确认同一身份；类别相同但身份歧义时中止。
6. D435 深度与 Lumos 帧差、帧龄、机器人 pose 差必须同时通过门限。
7. 精调最多执行配置的有限次数。第一版上限为 3 次；超过后报告
   `view_refinement_exhausted`，不得继续振荡。
8. 深度通过后使用掩码内点云的中位数/MAD 离群过滤和协方差估计；至少连续 5 个 stop-and-look
   样本稳定后才生成抓取预览。
9. 人工确认必须绑定最新预览的 `session_id`、`identity_id`、三维位置、标定 ID 和过期时间。
   新观测显示身份改变、目标位姿变化超过门限或证据超过有效期后，旧确认自动作废。

## 7. 运动策略

### 7.1 粗移动

- 仅允许移动到预教观察位；不依据未知深度直接向目标作自由笛卡尔接近。
- 观察位路径保持相机和夹爪在桌面安全高度以上，并避开已配置禁入区。
- 如果当前观察位已经覆盖目标并能取得合格深度，跳过粗移动。

### 7.2 精调

- 只在至少一组有效 D435 深度已经绑定到目标身份后启用。
- 优先使用相机横向/朝向的小修正，不沿未知或低置信度深度方向前冲。
- 每次只发送一个有界增量，然后停稳、重新识别、重新测深。
- 第一轮实机验证限制为速度比例不高于 0.05、单次笛卡尔平移不大于 20 mm、旋转不大于 5°，
  且每步人工确认。只有单独的实机验收记录通过后才允许调整这些门限。
- D435 有效测距下限和末端/物体/桌面间隙必须同时满足；进入近距离深度盲区前停止使用 D435
  更新，不把最后一个深度值无限延用。

### 7.3 观察与抓取分离

观察位不是预抓取位。获得三维目标后，从当前已知机器人状态重新生成完整的预抓取、下降、闭合、
抬升路径，并再次执行可达性和安全门禁。观察阶段的运动授权不能复用于抓取阶段。

实例点云中心也不等于夹爪抓取点。主动观察只输出带不确定度的目标几何观测；抓取规划器仍需
根据实例点云、夹爪宽度、桌面间隙和接近方向生成并验证独立抓取候选。主动观察成功不能直接
把目标标记为 `safety_approved`。

## 8. 异常和恢复

以下情况立即中止当前会话并撤销抓取预览：

- 目标身份丢失、歧义或变成其他实例；
- Lumos/D435 帧陈旧、时间差超限、相机断连；
- D435 无覆盖、有效点不足、深度跳变或位姿不确定度超限；
- 标定 ID、桌面版本、机器人模型或观察位目录在会话中改变；
- 机器人未到目标、反馈超时、意外运动或另一个控制者占用命令通道；
- 规划提案不可达、越界、超过步长/速度限制或缺少路径安全证据；
- 精调达到次数上限仍未获得合格深度。

中止后的默认动作是停止发送新命令并保持当前状态，不自动执行未经验证的“回退”运动。软件停止
或硬件急停后必须创建新会话；旧目标锁、深度和人工确认不得恢复使用。只有存在预教且验证过的
返回路径时，操作员才能单独命令回到安全位。

## 9. 配置与持久证据

新增配置应与 `configs/vision/remind3d.yaml`、`configs/workspace.yaml` 分离版本管理，并包含：

- 桌面平面及其验证报告哈希；
- D435 中央质量区和经实测验证的距离范围；
- 观察位、覆盖多边形、允许起始区和路径验证 ID；
- 粗位置不确定度门限、深度点数、稳定帧数和精调次数；
- 观察运动的速度、平移、旋转、settle 和超时限制；
- 实机执行与人工确认开关。

实时日志记录每次状态转换、输入帧号、机器人 pose、标定 ID、提案、授权结果、命令请求 ID、
完成反馈、拒绝原因和人工确认。日志必须能够离线重放同一决策。

## 10. 用户界面

相机页增加主动观察面板；在 Dry Run 阶段只显示信息，进入获批的实机阶段后才显示相应确认
控件。面板显示：

- 当前目标 `identity_id` 与锁定状态；
- Lumos 粗位置及“不用于抓取”的明确标记；
- 当前/候选观察位、D435 覆盖和深度质量；
- 会话状态、剩余精调次数和 fail-closed 原因；
- 最终三维位置、置信度、抓取轨迹预览及人工确认按钮。

运行中必须始终提供软件停止入口，并明确提示软件停止不替代物理急停。第一轮实机验证还需为
每个观察移动显示目标姿态、最大位移/转角并要求逐步确认。

## 11. 测试与验收

### 11.1 纯函数和合成测试

- Lumos SEUCM 射线与桌面平面求交、无交点和边缘畸变场景；
- D435 视锥在桌面的覆盖、多边形边界和不确定区域包含关系；
- 两相机基线导致的距离相关视差，禁止固定像素偏移；
- 观察位选择稳定性、无覆盖拒绝和代价排序；
- 精调步长/次数限制、中心区接受和“已有合格深度则不移动”；
- 会话 ID、迟到事件、过期确认和所有授权拒绝分支。

### 11.2 录像回放

录制鱼眼边缘目标、同类多实例、遮挡、移动后重入、D435 无覆盖、透明/反光物体、深度飞边、
帧时间差和相机断连。验收要求目标身份不因观察位切换而错误转移；歧义必须拒绝，不能强配。

### 11.3 模拟与 Dry Run

1. 不连接 CAN，只生成观察位提案和状态转换。
2. 使用模拟机器人回放 command-complete、超时、目标未到位和停止事件。
3. 在线真实双相机运行至少 30 分钟，执行始终关闭，验证会话不会产生任何机械臂 I/O。
4. 对每次提案保存预期 D435 覆盖，并用实际停稳帧评估覆盖命中率和深度质量提升。

### 11.4 标定门禁

沿用现有验收门限：Lumos 独立验证重投影 median ≤ 1 px、P95 ≤ 2.5 px、边缘 P95 ≤ 4 px；
双相机注册板角点 P95 ≤ 4 px、桌面平面 P95 ≤ 8 mm；手眼/全链静态点 P95 ≤ 10 mm。
任一门限失败时只允许 Dry Run，不允许真实主动观察或抓取。

### 11.5 分阶段实机验收

1. 操作员确认物理急停可用、工作区清空、桌面和安装未变化。
2. 断开夹爪负载或使用安全假目标，速度比例 ≤ 0.05，每个观察动作逐步确认。
3. 先只验证预教观察位，再启用最多一次 20 mm/5° 精调，最后增加到最多三次。
4. 验证目标身份、实际 D435 覆盖、深度稳定、停止行为和超时处理。
5. 通过独立记录后才允许生成抓取预览；首次抓取仍需人工确认。
6. 取消人工确认属于独立后续决策，不包含在本设计的第一版验收中。

## 12. 非目标

- 不让 D435 RGB 取代 Lumos 作为主语义相机。
- 不实现运动中的连续 RGB-D 融合或高速视觉伺服。
- 不在无 D435 深度时根据桌面交点直接抓取。
- 不绕过现有标定、身份、时间戳、可达性和抓取授权门禁。
- 不在本设计阶段启用真实机械臂执行。

## 13. 需要用户明确批准的节点

日常算法、配置结构和测试细节由实现方按本设计决定。只有以下节点必须再次取得用户明确批准：

1. 第一次发送真实机械臂观察运动前；
2. 用户确认现场急停、工作区清空和假目标条件满足后；
3. 分阶段验收完成后，是否允许真实抓取；
4. 后续是否取消抓取前人工确认并转为全自动。
