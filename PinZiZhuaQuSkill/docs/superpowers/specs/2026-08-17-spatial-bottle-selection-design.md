# 按画面左右顺序选择瓶子的视觉设计

日期：2026-08-17

## 目标与边界

视觉模块检测机械臂面前工作区内的所有瓶子，不区分品牌、包装或具体瓶种。候选按末端 XVisio 相机画面中的水平位置排序。未来语音模块传入方向和序号，例如 left + 2 表示左数第二瓶，right + 2 表示右数第二瓶。

视觉模块只输出相机坐标系夹取结果，不控制机械臂，不进行手眼标定、基坐标变换或语音识别。

## 选择语义

- 左右方向以固定观察姿态下的 RGB 画面为准。
- 使用实例掩膜质心的 x 坐标排序，不使用检测框左边缘。
- 只排序通过瓶子类别、实例掩膜、深度覆盖、工作距离和工作区检查的候选。
- 序号从 1 开始。左数时按 x 升序，右数时按 x 降序。
- 三个瓶子时，左二和右二都指向中间瓶；四个瓶子时，左二和右二指向不同瓶子。
- 请求序号超过有效瓶子数量时返回 requested_bottle_not_found，禁止改选。
- 两个水平中心过近、掩膜重叠严重或无法稳定分离时返回 spatial_order_ambiguous。

## 数据流

1. XVisio 输出同网格 RGB、深度和相机坐标 XYZ。
2. Grounding DINO 使用通用瓶子提示词产生候选。
3. SAM2 为候选生成独立实例掩膜。
4. 合并高度重叠的重复检测。
5. 使用深度覆盖、三维点数、工作距离和瓶状轮廓过滤不可夹取候选。
6. 按掩膜质心 x 坐标生成稳定的左右顺序。
7. 根据请求方向和序号选择目标，记录掩膜、二维质心、三维中心和首次选择帧。
8. 使用掩膜内 XYZ 估计夹取中心、瓶身轴线、接近方向和夹取宽度。
9. 最近 5 帧至少 4 帧稳定后输出 ready。

## 目标锁定

左右排序只在固定观察姿态选择目标时执行一次。选中后通过掩膜 IoU、二维中心运动和三维位置关联同一瓶子。相机或机械臂移动后不得重新排序并换目标。

目标连续丢失、出现两个合理关联、三维位置跳变、时间失效或观察周期改变时，立即解除授权并要求重新观察。

## 接口

输入为 RgbdFrame、selection_side（left 或 right）、requested_ordinal 正整数，以及未来可选的 selection_epoch。

输出包括 selected_ordinal、有效瓶子总数、实例掩膜、GraspPoseCamera、稳定命中数、深度覆盖率、有效点数和阻断原因。位姿坐标系固定为 xvisio_color，robot_control_enabled 始终为 false。

语音模块未来负责把“最左边”“左二”“最右边”“右二”等语言转换为方向和正整数。手眼模块未来负责把相机坐标结果转换到机械臂坐标系。

## 失效保护

- no_graspable_bottles
- requested_bottle_not_found
- spatial_order_ambiguous
- selected_track_lost
- selected_track_ambiguous
- depth_insufficient
- pose_spread_too_large

任何阻断都不能回退为检测框中心，也不能自动选择邻近瓶子。

## 对现有实现的影响

保留 XVisio RGB-D/XYZ、录制回放、SAM2、掩膜内 XYZ 几何、4/5 帧稳定授权、CLI 和 xvisio_color 输出。

删除固定可乐参考相似度和品牌竞争门。用通用 BottleCandidateFilter 替换 FixedBottleVerifier，增加空间排序、序号选择和选中后轨迹锁定。旧参考清单保留为历史文件，但新流程不读取。

## 3100 机械臂网站可视化接入

3100 端口继续由现有 ThirdHand Startouch 机械臂控制网站占用。VA 不启动第二个 3100 服务，不修改机械臂按钮、WebSocket、CAN 或夹爪逻辑，只提供与现有 CameraBridge 子进程协议兼容的 camera_bridge_va.py。

现有网站主摄像头区域为 camera-feed，数据源为 /camera。VA 桥接脚本在 stdout 输出 multipart MJPEG，画面已经包含视觉算法叠加，因此现有 /camera 路由可直接显示复杂视觉结果。fd3 输出 JSON 检测事件；fd4 可同步输出带完整来源头的算法叠加 MJPEG，兼容现有 /camera_lumos_vision 和 OverlaySnapshotAssembler。未使用的原始相机与深度热力图文件描述符仍保持可读或明确声明不可用，不能阻塞 Node 进程。

每帧可视化必须体现：

- 所有有效瓶子的半透明实例掩膜、轮廓和质心；
- 每个瓶子的左序号和右序号，例如 L2 / R3；
- 当前选择请求，例如 LEFT 2 或 RIGHT 2；
- 被选目标的粗绿色轮廓和 SELECTED 标记；
- 有效深度覆盖、三维夹取点、瓶身轴线和接近方向；
- 4/5 稳定命中、处理 FPS、延迟、ready 或阻断原因；
- robot_control_enabled=false。

浏览器或网络变慢时只保留最新帧并丢弃旧帧，不能让网页反压拖慢相机与视觉推理。发生相机、模型或深度错误时，叠加画面必须清除过期 ready 并显示错误状态。

当前 VA 仓库只交付兼容桥接脚本、协议测试和接入说明。未来组员合并时，在现有 CameraBridge 允许列表和 CAMERA_BRIDGE_SCRIPT 配置中加入 camera_bridge_va.py，即可把 VA 叠加流送入 3100 网站固定摄像头区域。

## 开发期间相机资源边界

手眼标定组员当前独占 XVisio 相机。空间选择和网站桥接实施期间禁止启动原生 XVisio 流、3100 网站相机桥、实时推理或任何会打开 USB 相机的程序。开发只使用合成 RGB-D/XYZ、已保存的录制包和假 CameraBridge 文件描述符完成。

相机实机测试是独立检查点，只有用户明确确认手眼标定释放相机后才能开始。相机仍被占用时，代码完成不等同于实机验收完成，状态必须明确标为 hardware_validation_pending。

## 测试与验收

离线测试覆盖三个和四个瓶子排序、掩膜质心排序、左二选择、右二选择、左右方向非法、序号越界、水平位置模糊、相机运动后的目标锁定、目标丢失、多目标冲突、三维跳变以及深度空洞。

实机验收覆盖 1、2、3、4 个瓶子的不同间距和摆放顺序，分别验证左一、左二、右一和右二。3100 网站验收确认主摄像头区域持续显示掩膜、左右编号、选择高亮、抓取点和阻断原因，全程不启动机器人控制。
