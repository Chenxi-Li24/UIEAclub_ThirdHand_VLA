# login分支 CI 修复

用户要求检查并修复CI。初始失败为[CI #20](https://github.com/Oliveirah007/UIEAclub_ThirdHand_VLA/actions/runs/41230970799)，提交0e4cb7d；test与public-access都在Node阶段失败，Python阶段尚未执行，不能视作Python通过。

## 原因与修改

1. **数据库清理竞态。** pg Pool.end在移除最后一个client后可能先返回，真实TCP的end回调还未完成。夹具随即DROP DATABASE FORCE，Linux快速返回57P01，导致已成功断言的账户、导出、会话测试被未处理连接错误标记失败。夹具现在在connect时登记client的end事件，pool.end后等待这些事件，再删除本次随机隔离库；仍拒绝非thirdhand_test数据库。新增真实PostgreSQL回归故意延迟transport关闭，旧代码复现同样57P01，新代码通过；没有屏蔽错误事件或改变业务连接池。
2. **控制拒绝与关闭握手竞态。** 旧代码发close帧，直到WebSocket close事件才关闭控制登记；客户端先收到关闭、服务端还没撤权，已有断言偶发读到lease_grant。修复在拒绝、超时或消息洪泛时先同步关闭登记，再发close帧，触发既有租约撤销/停止路径。新增无响应客户端回归：旧代码800ms超时，新代码在TCP仍开着时撤权。没有延长500ms挑战期限或放宽身份校验。
3. **来源绑定与CI资源。** 先前Robot只读远端租约/worker修改改变了两个生产者文件字节，旧只读frame policy仍绑定旧摘要。核对没有更改工具变换/姿态语义后，更新两件来源摘要、handeye policy_id及web-grasp引用；所有外参矩阵、pending物理验证、false抓取批准/硬件资格均保留。生产校验器不变，改字节仍拒绝。给这些内容绑定文件显式LF属性，防止Windows检出换行漂移；CI只额外恢复policy所绑定的两件已有SDK LFS库，不下载完整模型集。
4. **网页测试夹具。** main.js的模型模块已抽到robot-viewer.js，但旧VM测试移除imports后没有提供该模块和三个loader。夹具现加载真实viewer factory并补齐未实例化的导入桩；不改业务网页或删断言。
5. **提交拆分遗漏。** 之前将services/vision/src/config.js和server.js整份误归为时间采集候选，遗漏了已完成的私有相机凭据/loopback流路由，CI得到404而不是403。本次补入这两份已测试功能文件。它们不包含采集时间候选；其余7件driver/Python/native测试候选继续保留工作区。
6. **非root CI运行TLS测试。** 公网Node通过后，先前未执行的edge Python检查有82通过/2失败：临时key.pem属于runner，生产维护器正确拒绝非root私钥。单元夹具现在显式提供可控的POSIX所有者元数据，证书/命令仍为合成与mock；新增非root所有者在任何命令前被拒绝的反例。生产TLS维护器及root/0600要求不变，不运行真实Nginx、签发或修改证书。
7. **LFS指针被误当成SDK载荷。** 继续逐项比对全部9个绑定后，发现旧配置的两个库摘要其实是131字节LFS指针文本摘要，不能代表库文件。本地恢复已有900272/287008字节载荷，并核对SHA等于仓库LFS对象ID8284d216…/56627356…。配置改为真实载荷摘要；校验器新增明确拒绝未恢复LFS指针，即使配置误记录了指针自身SHA也不能通过。该反例旧代码RED、新代码GREEN。没有更换SDK版本、运行库或批准硬件。
8. **一次性固定目标工具与源码边界。** 补跑先前未执行的审计发现5份已审阅运维工具的13处固定Ubuntu路径。改变它们的目标会破坏原先固定范围/安装器摘要，故保留原字节。`configs/audit/site-bound-operations.json`逐件记录已有工具的LF规范内容SHA及用途；审计仅对这些字节完全一致的工具允许home路径。未知工具、运行源码、任何改动后的工具仍失败，History/符号链接/私有运行数据等其他规则继续执行。5项测试覆盖每个边界，整仓审计通过；没有整个目录忽略或跳过审计。
