# 登录等待反馈与超时恢复

状态：本地实现及浏览器验证完成；尚未部署 staging。

## 本次发现与行为

用户报告提交登录后页面一直转圈。本轮随后观察到同一 staging 标签页已进入管理员工作台并渲染模型，说明这次登录最终成功；不能据此归因为密码错误。线上 Nginx 配置关闭了 access_log，没有这次请求的分段耗时证据，不能确定是网络、认证处理、偏好加载还是页面导航延迟。

源码中登录请求及偏好读取没有等待上限，按钮仅 disabled，缺少明确的进行中反馈。现在提交后立即显示灰色不可点击按钮、转圈和“请求已发送，请稍候，不要重复提交”；身份模式选择也暂时禁用。请求最长等待 15 秒，超时终止前端等待、恢复手动重试并提示，绝不自动重复提交密码。超时不等于服务端一定没有创建会话。

认证成功后分别显示“加载偏好”和“打开工作台”。偏好最多等待 5 秒，之后由工作台读取既存偏好，不清空用户设置。导航等待超过 15 秒显示“打开工作台”按钮，只重试导航，不再发送认证请求，避免重复登录触发限流。支持中英文、屏幕阅读器状态提示及减少动画偏好。

## 模块与数据流

- `apps/web/public/js/auth-page.js`：提交状态、AbortController、超时边界、认证成功后的导航重试。
- `apps/web/public/css/auth.css`：灰色禁用按钮、居中转圈、提示间距与减少动画。
- `apps/web/public/js/i18n-auth-catalog.js`：中英文反馈。
- 沿用 `POST /api/v1/auth/login` 和现有偏好接口，无 API 合约、数据库、权限、依赖或配置变化。密码、验证码不写日志、不持久化；成功后清空输入。
- 本地和云端均沿用既有业务服务启动方式；部署只需这三件前端文件进入固定 release，并重启既有业务 API 以更新资源摘要。无新增资源、SDK 或 Ubuntu 操作。
