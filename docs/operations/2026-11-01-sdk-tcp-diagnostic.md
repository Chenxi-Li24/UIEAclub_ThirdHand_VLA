2026-11-01 用户完成 Observer 登录后，仅申请 SDK 连接租约，没有点击连接确认、初始化 SDK 或发送后续运动。沿用云端发布 3d3acd1d9fa353a0。没有代码、数据库结构、权限、网络配置或服务重启变更。

本轮直接观察到设备 WSS 通道的云端下行报文重传：同一 TCP 序列范围发送三次，Ubuntu 仅收到第三次。它与授权失效发生在同一窗口，证明当前设备通道存在显著传输延迟；不能仅凭该记录区分无线接入、校园出口、公网或云侧网络，也不能将所有 renewal_failed 都归因为同一种异常。

SDK 连续十分钟真实状态验收仍未完成。设备页面显示过期数据，没有将模型姿态作为真机反馈。

## 方法与边界

- Ubuntu 原有管理连接经 Tailscale；实际设备业务 TCP 仍连接公网 47.94.95.244:443，走 wlp7s0。只读检查云端未安装 tailscale，不能把当前业务通道描述为 Tailscale 隧道。
- 21:26:55（北京时间）确认 power_save=on；此前独立恢复服务 Result=success、ExecMainStatus=0。本轮不再关闭节电。
- 通过 TCP 字节计数与报文序号匹配设备的既有长连接，两端仅过滤这个连接。云端 timeout 90 秒、Ubuntu timeout 60 秒；tcpdump 仅输出时间、地址、TCP 序号、确认号和长度，未输出载荷、令牌或私钥，未保存原始 pcap。
- 云端 189 包、Ubuntu 134 包，均报告内核丢包 0；窗口长度不同，包数不用于计算网络丢包率。两端均按时退出，timeout 的退出码不代表捕获失败。
- 云端元数据文件只对 root 可读。原始输出和截图作为运行证据保留，不提交 Git。

## 同一失败窗口的证据

以下时间为 UTC，转换北京时间加八小时。

| 事件 | 时间 / 结果 |
|---|---|
| 云端租约请求 | 13:30:50.151 |
| 云端租约确认 | 13:30:50.203 |
| 云端租约释放 | 13:30:52.132；scope=sdk；renewal_sequence=4；reason=renewal_failed |
| 云端首次发送同一 903 字节 TCP 范围 | 13:30:51.049886；seq 4151928082:4151928985；TS val 2139948476 |
| 云端第一次重传 | 13:30:51.350569；同一 seq；TS val 2139948777 |
| 云端第二次重传 | 13:30:51.638568；同一 seq；TS val 2139949065 |
| Ubuntu 捕获到该范围 | 13:30:51.717367；TS val 2139949065，与第三次发送匹配 |
| Ubuntu 接收后发出结果 | 13:30:51.718829；218 字节 |
| 云端收到该结果 | 13:30:51.849813 |
| Ubuntu 续期事件 | 13:30:51.718；remote_lease_renew active=true |
| Ubuntu 撤销 / 到期事件 | 13:30:52.048 revoke；13:30:52.065 lease_expired |
| 设备停止回执 | ALREADY_STOPPED；SDK 此前就未连接 |

两次重传相对首发累计 588.682 毫秒，是同一云端时钟上的差值，不依赖两机时钟同步。跨机时间仅用于对应窗口，不作为精确单向延迟；序号及 TCP 时间戳确认收到的是第三次发送。903 字节载荷未解密，结合续期事件可以对应续期窗口，但不宣称从抓包读取了应用报文。

云端 renewal_failed 是汇总原因，当前日志未保留内部异常码；本次最后一次续期在设备端仍返回 active，因此不能把它误记为 renewal_unconfirmed。需要更细的受限错误分类，才能区分后续浏览器新鲜度检查、传输请求异常或其他续期前置检查。

云端最新 connect 仍是 05:34:56.44 的旧记录，本轮没有新增 connect。前置只读检查 sdkConnected=false、readOnly=true、moving=false、fixedTcpDemoActive=false；recordingHealthy=true、videoHealthy=false。
