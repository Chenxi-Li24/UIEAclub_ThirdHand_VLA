## 原因与修复

前次真实分段诊断得到3条完整续期链，其中两条在代理校验后、本地 Robot HTTP 前拒绝；接收墙钟减签发时间为约 -10.104ms、-0.481ms，完整往返40–111ms。证据见[诊断记录](2026-11-02-sdk-segment-timing-change.md)。这是时钟差与传输耗时的合成值，不能据此精确推算两台主机的 NTP 偏差。

旧校验把 `expiresAt - Ubuntu当前时间 <= 1000ms` 当作签名租约的长度限制。云端签发1000ms，而 Ubuntu 时钟略早时，剩余值可能成为1010ms；通用协议允许的既有500ms未来签发容差与该检查矛盾。修复统一三个层级：

| 模块 | 修改及保留的限制 |
|---|---|
| edge-agent/thirdhand_edge/lease.py | 校验签名跨度 `0 < expiresAt-issuedAt <= 1000`；签名、上下文、有效期、未来签发不超过500ms仍检查 |
| robot/control-policy.js | 同样按签名跨度校验；向本地看门狗传递 `min(1000, expiresAt-wall)`，不把偏差转成更长本地授权 |
| robot/remote_lease_guard.py | 去掉跨主机剩余值必须≤1000的重复拒绝；仍取本地单调时间+1秒、墙钟剩余值、首次墙钟/单调时间锚点三者最早截止 |

过期、序号重放、旧generation、错误签名仍拒绝；已过期租约不能被迟到续期恢复。现有500ms浏览器新鲜度、1000ms签名跨度/本地上限、1500ms ACK等待、最多4条在途续期均不改。没有把单次续期延长为2秒或3秒，也没有修改系统时间、NTP、Wi-Fi或Tailscale。

## 网页申请反馈

`admin-control.js`在申请开始立即禁用该按钮、标记aria-busy、显示“正在申请授权…”以及“请求已发送，正在检查浏览器和设备授权”；申请期间锁定设备选择，客户端也拒绝重复申请。通道打开时不会把等待提示覆盖成“没有租约”。

设备拒绝、请求超时、会话无权限、浏览器失效分别显示原因，失败后恢复申请按钮。沿用现有请求12秒超时和绑定4秒超时，不自动重试。请求结果不能推断真实SDK连接或物理停止状态。

授权成功显示“SDK授权已生效，请点击‘连接SDK’进行初始化”。申请授权本身不初始化SDK；连接仍必须显式确认电机使能与默认闭爪副作用。`i18n-cloud-catalog.js`提供对应中英文。模型滑条与仿真点位不受影响；管理员运动权限规则、只读门禁不变。
