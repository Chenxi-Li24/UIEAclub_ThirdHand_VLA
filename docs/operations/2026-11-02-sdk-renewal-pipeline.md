本地回归先在旧代码失败：第一次设备确认被延迟时，即使250ms后收到新的有效浏览器响应，第二次续期也不会发送。旧队列虽保留最新事件，但仍必须等待上一ACK，令返回链路延迟阻塞下一次下行；不是每条续期各自一秒TTL失效后的自动重试。

## 实现

- services/cloud-api/src/control/leases.js：异步身份/准备状态/数据库续期/发送按持有者串行，等待ACK与发送队列分离。最多4条续期等待ACK，满额时只保留一个最新浏览器事件。ACK释放容量后只有存在待处理新事件才继续，每次重新校验500ms浏览器新鲜度、持有者、当前设备绑定和数据库有效租约。
- 发送后仍等待真实匹配ACK确认，任一失败按原规则撤销并请求停止；已撤销的旧ACK不能恢复授权。乱序成功ACK不能回退holder的renewalSequence。
- services/device-relay/src/server.js：增加内部devices.dispatch，完成证书注册校验和WebSocket发送后返回独立confirmation Promise。现有request包装dispatch并等待确认，原SDK命令和停止行为保持不变。不能仅把原async request调用当作发送完成，因为其内部还有异步凭据复核，可能导致顺序颠倒。
- 不具备dispatch边界的旧适配器保持等待完整ACK的串行行为。真实Node中继支持此边界；Python设备既有lease_lock继续串行处理签名租约，无Ubuntu变更。

## 保持的限制

签名仍是发送时刻起1000ms，不使用未来issuedAt、不提前签发；浏览器500ms、数据库过期不可复活、设备单调看门狗、签名/绑定/序列/角色/readOnly判断均不变。不自动重试失败请求、重新申请租约、初始化SDK或流水发送运动命令。

中继现有普通请求上限8、优先停止保留第9个位置不变；自动续期最多占4。没有新心跳不持续续期，取消/登出/断线/拒绝仍终止。网络下行阻塞超过有效期仍应断开；此修复解决ACK等待造成的额外串行延迟，不承诺消除校园网问题。
