## 样本与范围限制

本轮恢复操作后，代理仅点击了一次“申请 SDK 连接”，没有点击“连接 SDK”。事后审计显示，同一观察窗口11:46:08.740—11:46:35.702（北京时间）实际已有12条申请，其中2条确认、10条grant_failed；不能把它描述为严格受控的三次试验，也不能仅凭这些记录判定其他申请由谁触发。发现后停止追加申请，检查活动租约及在途命令均0。后续诊断应先检查已有申请计数，并避免多个页面／人员同时提交。

两条确认的授权分别因 `renewal_unconfirmed` 释放。三条续期均有 cloud／relay／edge 完整关联，合计9条匿名计时记录：1条active，2条rejected；没有缺失段或重复段。未记录初始化动作，因此故障发生在SDK库调用之前。

## 定位及离线复现

当前云端签发 `expiresAt = issuedAt + 1000`。代理 `thirdhand_edge/lease.py` 在验签后又检查 `expiresAt - deviceNow > 1000`；当设备时钟略落后于签发时间，这个条件即成立。Robot Node `control-policy.js` 和 Python `remote_lease_guard.py` 也有相同剩余时长限制。协议第一层则允许签发时间最多领先本地500ms，因此出现“第一层通过、下一层拒绝”的不一致。

用本地生成的临时测试密钥、假时钟和现有未修改实现复现：设备时间相对签发为−10／−1ms时，通用验签通过，租约返回 `INVALID_LEASE`，worker返回 `REMOTE_LEASE_EXPIRED`；0／1／10／58／999ms通过；1000ms到期拒绝。8组、24项断言通过，无SDK/CAN导入或网络请求。复现脚本 `reproduce-clock-boundary.py` 保存在本地证据目录。

结论：**已复现毫秒级时钟差导致的校验边界缺陷，并与本次现场拒绝阶段一致。** 现场通用异常处理仅输出 `DEVICE_REQUEST_REJECTED`，未记录内部异常类型；因此该归因有强证据，但修复后仍需同窗口复测，不能声称已解释所有历史掉线。此前网络重传证据仍成立，本轮三条样本不代表长期网络稳定。

## 下一步具体修改（待实现与固定候选部署）

1. 优先统一代理、Robot Node、Python guard三层的时间语义：独立校验签名有效跨度 `0 < expiresAt-issuedAt <= 1000`、既有未来时间容差与绝对过期；本地单调截止使用保守上限，不超过接收后1000ms，并保持既有锚点和旧租约到期保护。禁止只删掉一层判断或把1000改大。
2. Node watchdog接收的剩余时长也必须一致裁剪；校验跨度与实际允许持续时长分开。保留500ms浏览器新鲜度、1500ms ACK等待、最大4条在途续期、scope/角色校验和readOnly门禁。时钟回拨、旧epoch、重复序号、队列迟到不允许延长旧授权。该方案改变边界语义，须做安全边界测试并形成新固定部署包，不能把诊断批准视为上线批准。
3. 补充匿名错误分类，区分签名、时间跨度、已过期、上下文及本地执行失败；仅允许固定错误码，不记录载荷或凭据。当前通用拒绝掩盖了直接原因。
4. 自动化覆盖±1／±10／±100ms、超过既有未来容差、1000ms边界、过长签名跨度、时钟跳变、乱序续期及超时后不得复活；跨Node/Python契约测试必须验证实际单调截止仍不超过1000ms。
5. 新包通过测试、审阅部署后，先做受控的授权持续测试；再开展已批准范围内的真实SDK连接和10分钟状态读取。只有成功通过，才能报告稳定连接。
6. SDK生命周期、多人只读订阅、管理员独占运动租约按[分离方案](2026-11-02-sdk-separation-design.md)逐层实施。2s／3s只读保持为后续独立评审候选，本次未应用；运动失效处理保持原策略。
