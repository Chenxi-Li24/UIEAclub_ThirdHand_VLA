# Feature-first onboarding v2 — 2026-11-13

The workspace guide now prioritizes System Check, AI Agent and Digital Twin preview/confirmation. Six short lessons cover readiness, describing an action, exploring the model, reviewing a preview and permissions, camera access, and supporting waypoints/history. Calibration is contextual page help, not a headline promise of completed grasping functionality. All guide text remains English regardless of a previously saved locale.

The guest renderer now loads the existing onboarding and spotlight scripts through its bounded public asset allowlist. Guests see a welcome/checklist on Digital Twin, a Getting started sidebar entry and contextual Page help. Authenticated/local workspaces continue using the same guide implementation with mode-appropriate descriptions. Guest copy explicitly describes skipped hardware checks, two-second public camera images, browser-local poses, private real history and control permission requirements. It does not claim that AI sees the camera or that guest voice input works.

Use example prompt only fills the text composer and focuses it. It neither submits an AI request nor activates a robot control. A six-step progress bar, Back/Next/Close, Escape dismissal and resumable progress keep the guide optional. Storage key `thirdhand.onboarding.v2` isolates the new lessons from obsolete v1 completion. No database migration, provider configuration or new dependency.

The checklist separates informational acknowledgments from actual practice: reading the system/camera lessons can complete those informational tasks; AI reply and preview events are emitted by the guest module only after successful response/application. Orbit requires a user-started camera change. Slider progress requires a valid changed model angle. Finishing the tour alone does not mark practical tasks complete. The guest module binds its scene and arm to the shell for progress tracking. Busy motion/teaching guards and permission prompts remain intact.

Modules: `apps/web/public/js/onboarding.js`, `apps/web/public/css/onboarding.css`, `apps/web/public/js/guest-workspace.js`, `services/cloud-api/src/guest-pages.js`. Existing spotlight positioning is reused. Resize now re-resolves responsive targets, and hidden primary targets cannot be acknowledged solely because a secondary highlight remains visible. No new HTTP endpoint.

Validation: 21 Node tests across onboarding, spotlight geometry and guest workspace passed. A logged-out public browser completed all six lessons at 390x844 without horizontal overflow. The example filled the J1=20 prompt with zero AI requests; the full tour generated zero control requests. Mobile step targets and the panel remained usable. Actual phone/WeChat hardware testing is still separate from browser viewport testing.

Public deployment: `/opt/thirdhand-stage/releases/guide-v2-20261113`; prior release `/opt/thirdhand-stage/releases/guest-ai-20261113`. Existing AI/camera environment files and Nginx routes are unchanged. Startup remains `thirdhand-stage.service`. Rollback atomically restores the prior current symlink and restarts that service. Guide state is browser-local and may be reset by removing only `thirdhand.onboarding.v2` from localStorage.
