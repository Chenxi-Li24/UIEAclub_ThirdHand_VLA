# Fixed Pick and Place 网页控制与连续轨迹设计

日期：2026-07-29
工作树：`/home/nieqingcao/arm/UIEAclub_ThirdHand_VLA-fixed-pick-place`
分支：`fanxy/fixed-pick-place`

## 目标

在不重做已验证 A/B 点位、25 cm 抬升路径、15% 速度和自适应夹爪逻辑的前提下：

1. 提供只包含“开始、停止、状态、日志”的本机网页演示入口。
2. 消除当前每 12° 子命令都减速到零造成的顿挫。
3. 保持资源独占、异常 cleanup、日志和现有一键脚本的安全约束。

## 已确认行为

- “停止”立即中断由本控制页启动的演示进程，执行 cleanup 和电机失能。
- 停止后机械臂留在当前位置，不自动回 Home。
- 控制页不得停止或干预其他用户、SSH 会话或控制进程。
- 发现 can0、工作树或机械臂已被占用时，显示 `RESOURCE_CONFLICT` 并拒绝启动。

## 方案

采用独立的演示控制服务，不复用会常驻 Startouch bridge 的手动控制服务。

控制服务本身不连接 can0。点击“开始”后，它仅启动现有
`scripts/demo_fixed_pick_place.sh`，保存子进程 PID，并转发状态和日志。
点击“停止”只向自己创建的进程组发送 SIGINT；演示脚本和 runner 的
`finally` 路径负责 cleanup。服务退出时同样停止并清理自己的活动子进程。

状态机：

`IDLE -> PREFLIGHT -> COUNTDOWN -> RUNNING -> COMPLETE|FAILED|STOPPED`

同一时刻最多一个演示子进程。开始按钮在非 IDLE 期间禁用；停止按钮只在
本服务拥有活动子进程时启用。

## 连续轨迹

当前 runner 将大角度运动拆为多个 12° 命令。每个命令独立调用
`set_joint_waypoints([current, target])`，SDK 每次都完成减速并回到 IDLE，
因此出现明显顿挫。

新实现仍按最大 12° 生成安全插值点，但把一个逻辑路段的全部插值点通过
一个 bridge 命令一次提交给 SDK：

`set_joint_waypoints([current, p1, p2, ..., target], time_sec=...)`

这样插值点用于限制相邻关节增量，却不再是独立启停命令。机械臂只在必须
执行夹爪动作或改变任务阶段的逻辑点停稳：

- Home
- A 上方、A 抓取点
- B 上方、B 放置/抓取点
- 最终 Home

总时长继续依据关节最大速度和 15% 速度比例计算；最终点继续校验反馈误差。
任一插值点 NaN、全零或超限均拒绝执行。

## 安全与资源边界

- 网页服务空闲时不持有 can0。
- 启动前复用一键脚本的目录、分支、can0、点位、速度、日志和进程检查。
- 不提供“结束其他进程”功能。
- `RESOURCE_CONFLICT` 原样显示，并保留完整日志。
- 软件停止不是硬件急停；现场仍需人员在场并确认急停可用。
- 真机首次连续轨迹验证使用 3% 速度和逐步确认；空载验证成功后才恢复已验证的
  15% 演示速度。

## 网页

页面显示：

- 工作树、分支、速度、循环次数、can0 状态
- 当前任务状态和阶段
- “开始演示”“停止并失能”按钮
- 实时日志和最后日志文件路径

Ubuntu 桌面通过本机地址打开，不对外网发布。

## 测试与验收

先写失败测试，再实现：

1. runner 能生成相邻增量不超过限制的多点轨迹。
2. 每个逻辑路段只向 bridge 发送一次运动命令。
3. bridge 验证并一次调用 SDK 多点接口。
4. 停止只作用于控制页拥有的子进程，并进入 cleanup。
5. 资源冲突时拒绝启动且输出 `RESOURCE_CONFLICT`。
6. simulate、dry-run 和网页 API 测试全部通过。
7. Ubuntu 页面可打开，空闲时无 can0 控制进程。
8. 现场确认后，以 3% 空载逐步验证连续轨迹；通过后再进行 15% 实物验证。
