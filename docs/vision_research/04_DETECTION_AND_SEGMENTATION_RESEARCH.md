# 检测与实例分割研究

## 任务需求

目标是瓶、杯、罐、盒和常见桌面物体。抓取定位需要对象表面而非 bbox 中心，因此实例 mask 的价值高于单纯提高 COCO box AP：mask 可过滤桌面/背景深度、计算对象点云、估计主轴和可见度，并更准确地判断遮挡。

## 候选模型

| 候选 | 能力 | 许可 | RTX 5060 8GB 适配 | 决策 |
|---|---|---|---|---|
| 当前 YOLOv8n detect | COCO box，部署简单 | Ultralytics AGPL-3.0 或商业许可 | 已运行但强制 CPU | 只作可复现基线 |
| YOLOv8/11 nano-seg | box+mask，易迁移现有代码 | AGPL-3.0/商业许可 | 很可能满足实时性 | 研究/开源条件允许时的快速增强 |
| RTMDet-tiny-ins（MMDetection） | 实时实例分割、Apache-2.0 | Apache-2.0 | 合理，需实际 benchmark | 首选可分发增强候选 |
| Mask R-CNN R50-FPN | 成熟、易微调 | Detectron2 Apache-2.0 | 可运行但延迟较高 | 精度/数据基线 |
| RT-DETR R18 | 实时 box 检测 | Apache-2.0 | 合理 | 检测对照，不解决 mask |
| SAM 2.1 small/tiny | 提示式图像/视频分割与记忆 | Apache-2.0 | 8GB 边界需实测 | 研究扩展，不作首个在线检测器 |
| GroundingDINO + SAM2 | 开放词汇检测+分割 | 核心仓库 Apache-2.0，权重另审 | 延迟/显存较高 | 数据标注、失败恢复或人工选目标 |

## 工程筛选

第一阶段不立即替换模型。先把接口、录制回放、指标和几何链建好，用当前 YOLOv8n 形成基线；随后在同一 Lumos 回放集上比较 YOLO-seg 与 RTMDet-ins。最终选择由目标类别召回、mask AP、边缘环带性能、延迟、显存和许可共同决定。

“COCO 上更高 AP”不能替代本机数据验证。当前模型遗漏 can，且 wine glass/cup/bottle 类别容易混淆；盒子类别也没有统一映射。需要自定义类别层：`bottle, cup, can, box, other_pickable`，语义类别与抓取几何分离。

## 数据策略

- 录制 Lumos 原始 1280×1280、D435 深度、相机时间戳、机器人姿态（只读）与标定版本。
- 训练/验证/测试按“场景和录制序列”划分，禁止相邻帧跨集合。
- 覆盖不同径向位置、距离、姿态、遮挡、反光/透明、手臂自遮挡和多个同类对象。
- 先用模型生成候选，再人工修正 mask；SAM2 可辅助标注但不作为真值来源。
- 明确空场景负样本和非可抓取相似物，控制误检。

## 指标与门限

- COCO box AP50:95、mask AP50:95、每类 precision/recall。
- 抓取相关指标：目标 mask recall、mask 边界 IoU、对象点云纯度、有效深度覆盖率。
- 分桶：中心/中环/边缘、遮挡比例、对象像素面积、距离和材质。
- 性能：采集到结果 P50/P95、模型 GPU 时间、端到端 FPS、峰值显存、掉帧率。
- 接受目标：目标类 recall ≥0.90，关键对象漏检率 ≤5%，P95 端到端检测延迟 ≤150 ms（增强模型），8GB 显存下无 OOM。最终数值必须用本机回放确认。

## 拒绝项

- 不用 bbox 中心单像素深度代表整个物体。
- 不在无本机 benchmark 时直接部署大型开放词汇模型。
- 不把 SAM 自动 mask 当作类别检测和稳定身份。
- 不用 D435 RGB 替代 Lumos 主视觉，只允许调试和故障回退。
