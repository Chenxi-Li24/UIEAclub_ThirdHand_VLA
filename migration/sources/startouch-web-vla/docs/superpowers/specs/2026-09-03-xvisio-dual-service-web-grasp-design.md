# XVisio 双服务网页夹取设计

## 目标

第一阶段保留两个独立服务：

- `3000`：现有 Startouch 真机网页与控制服务。
- `3100`：现有 XVisio RGB-D、瓶子检测、分割和抓取预览服务。

用户只访问 `3000`。`3000` 代理 `3100` 的视频和只读视觉状态，并在本地完成目标授权与夹取状态机控制。视觉进程不能直接连接 CAN 或向机械臂发送运动命令。

## 非目标

- 本阶段不把视觉 Python 进程合并进 `3000` 服务。
- 不绕过手眼标定物理验收或硬件激活锁。
- 不允许浏览器提交机器人基坐标、关节角或未经信任的抓取位姿。
- 不在夹取完成后自动回零、移动到放置点或松开夹爪。

## 服务边界

```text
浏览器
  -> 3000 /camera/xvisio/raw -----------------> 3100 /camera_lumos
  -> 3000 /camera/xvisio/vision --------------> 3100 /camera_lumos_vision
  -> 3000 /api/vision/status -----------------> 3100 /api/vision/status
  -> 3000 /ws
       -> 目标选择请求 ------------------------> 3100 /ws
       -> 夹取命令 -> 安全授权 -> Startouch SDK -> can0
```

`3000` 是唯一控制权限边界。`3100` 只提供图像、检测结果、深度位姿、标定证据和选择状态。即使 `3100` 被错误配置，也不能直接驱动机器人。

## 视觉转发

`3000` 增加固定上游配置 `XVISION_SERVICE_URL`，默认 `http://127.0.0.1:3100`。只允许代理以下固定路径，不接受浏览器指定任意上游 URL：

- `/camera/xvisio/raw` -> `/camera_lumos`
- `/camera/xvisio/vision` -> `/camera_lumos_vision`
- `/api/vision/status` -> `/api/vision/status`

MJPEG 转发保持流式背压、禁用缓存，并在浏览器断开时关闭上游请求。视觉状态设置短超时并进行结构化校验；上游不可用时返回 `503`，同时关闭所有夹取按钮。

`3000` 连接 `3100/ws`，接收 `thirdhand-va-detection-v2` 事件。服务端把 `targets`、顶层 `pose` 和选中目标的 `grasp_preview` 规范化为可信目标，浏览器只接收显示字段。目标坐标始终来自服务端视觉事件，不能由网页回传。

## 目标选择

右侧目标列表显示检测 ID、左右顺序（例如 `L1/R3`）、置信度、深度有效率、夹取宽度和安全状态。用户点击目标后，浏览器只发送：

```json
{"cmd":"select_vision_target","side":"left","ordinal":1}
```

`3000` 校验 `side` 和 `ordinal` 后转发为 `select_bottle`。选中目标必须连续稳定，且返回的左右顺序与请求一致。重复或重叠候选导致顺序不一致时，目标保持锁定失败，网页显示“目标有歧义”，不得夹取。

## 网页界面

原“D435 视觉”区改名为“XVisio 视觉”。删除重复的第二路 Lumos 小画面，保留一个稳定尺寸的视频区域。

- 默认显示带检测框和选中目标的识别流。
- 提供“识别 / 原始”分段切换。
- 视频下方显示视觉在线状态、目标列表和当前抓取预览。
- 夹取模式使用“分步 / 自动”分段切换。
- 分步模式依次启用“移动到悬停点”“下降”“夹紧”“抬升”。
- 自动模式提供“开始自动夹取”，执行悬停、下降、夹紧和抬升。
- “取消任务”只停止后续步骤；紧急情况仍使用现有软件停止和独立硬件急停。

网页刷新、视频加载和 WebSocket 重连不得连接机械臂、启动运动或继续中断前的夹取任务。

## 夹取状态机

共享状态机阶段如下：

```text
idle -> target_selected -> preview_ready -> hover -> descend -> close -> lift -> holding
                                      \-> aborted
```

分步模式每次确认最多推进一个运动阶段。自动模式在一次明确点击后连续推进，但每个阶段开始前仍重新执行安全检查。完成状态为 `holding`，机械臂停止且夹爪保持闭合。

每次任务绑定以下证据：

- 目标 identity/detection ID；
- `preview_id` 和标定内容哈希；
- 视觉观测时间；
- 抓取点、悬停点和夹取宽度；
- 任务开始时的机械臂状态。

任何目标丢失、证据变化、视觉超时、机械臂状态超时、运动失败或夹爪失败都会进入 `aborted`，不再发送下一步命令。

## 安全授权

开始任务和每个阶段前必须同时满足：

- Startouch SDK 已连接且状态为 `IDLE`；
- 当前没有其他关节、笛卡尔、夹爪或主动观察动作；
- 视觉事件未超过 250 ms；
- 目标身份已确认且不存在排序歧义；
- 深度有效、抓取位姿有限且位于工作空间内；
- 手眼标定 `physical_validation.status` 为 `passed`；
- 实测误差不超过标定文件要求的 10 mm；
- `camera_mount_id_activation` 和 `approved_for_bottle_grasp` 均为 `true`；
- 服务端显式启用视觉执行；
- 夹取任务使用低速限制。

当前标定仍为 `pending`，因此实现部署后界面只能选择目标和查看预览，A/B 两种夹取按钮均保持禁用。不得通过前端参数或仅编辑布尔值解除门禁。

## 运动策略

运动点只使用经过授权的 `grasp_preview`：

1. `hover`：移动到预抓取点。
2. `descend`：保持授权姿态移动到抓取点。
3. `close`：根据视觉宽度换算夹爪目标，并检查反馈是否达到容差。
4. `lift`：回到安全抬升点，保持夹爪闭合。

不得复用旧状态机中的自动 `go_home` 和自动松爪行为。运动时间由距离、低速上限和现有 Startouch 限位共同计算，不能由浏览器指定。

## 错误处理

- `3100` 不可用：视频显示离线，清除可信目标并禁用夹取。
- 视觉帧过期：清除预览，任务未开始时回到 `idle`，已开始时转为 `aborted`。
- 目标重复或顺序变化：显示歧义原因，要求重新选择。
- 机器人断开或运动错误：终止状态机并保留最后位置，不自动回零。
- 夹爪未到位：终止后续抬升，提示操作者检查目标和夹爪。
- 软件停止：立即终止任务并调用现有 SDK cleanup；它不替代硬件急停。

## 测试与验收

自动测试覆盖：

- 固定上游路径代理和上游不可用处理；
- `thirdhand-va-detection-v2` 到可信目标的规范化；
- 浏览器坐标注入被忽略；
- 未通过标定时 A/B 按钮和服务端命令均被拒绝；
- 分步模式每次确认只推进一步；
- 自动模式按顺序执行并停在 `holding`；
- 目标过期、证据变化、运动失败和夹爪失败均终止序列；
- 页面默认使用识别流，并能切换到原始流；
- 页面加载和重连不会触发机器人动作。

软件验收先在 `STARTOUCH_SIMULATE=1` 下完成。真机验收必须在物理标定通过后依次进行：只读预览、单次悬停、分步完整夹取、自动完整夹取。每一步由现场人员确认工作区清空且硬件急停可触达。

## 后续迁移

双服务方案稳定后，可把 XVisio bridge 作为 `3000` 的受管子进程，保留相同的内部视觉事件合同和网页协议。迁移不得改变安全授权条件或浏览器信任边界。
