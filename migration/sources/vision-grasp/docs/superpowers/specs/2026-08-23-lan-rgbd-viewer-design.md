# Windows 局域网 RGB-D 融合画面查看设计

日期：2026-08-23

## 目标

在 Ubuntu 主机上继续完成 RGB 相机画面、瓶子算法可视化和深度热力图的逐帧融合，
通过同一局域网把最终只读视频发送到 Windows。Windows 使用 Edge、Chrome 或 VLC
直接打开视频地址，不依赖 VS Code Remote-SSH，也不传输 Ubuntu 整个桌面。

## 现有系统与边界

- Ubuntu 局域网地址当前为 `192.168.58.68/24`。
- 端口 3000 的现有服务仅监听 `127.0.0.1`，同时承载视觉数据与其他业务接口；不得
  改为局域网监听。
- 端口 8765 和 8766 已被现有只读预览服务使用；不得停止、复用或改变其监听方式。
- 本地算法源为 `http://127.0.0.1:3000/camera_lumos_vision`，深度源为
  `http://127.0.0.1:3000/camera_xvisio_depth`。
- `thirdhand_va.vision.preview` 负责来源、精确帧号同步和视频发布；
  `thirdhand_va.vision.visualization` 继续负责纯图像融合；网络服务不得包含机器人控制。

## 推荐方案

新增一个独立、只读的局域网融合视频应用。应用在 Ubuntu 内部读取现有两个 loopback
视频源，按照 `X-ThirdHand-Frame-Id` 精确配对，再复用现有深度融合函数生成最终 JPEG。
它仅在 `192.168.58.68:8770` 监听，不改变任何现有端口和上游进程。

Windows 通过以下形式的地址查看：

```text
http://192.168.58.68:8770/stream.mjpg?token=<启动时生成的访问令牌>
```

该地址传输的是最终视频内容，不包含 Ubuntu 窗口边框和桌面。视频流量直接经过局域网，
不经过 SSH、VS Code 端口转发或 ToDesk。

## 模块设计

### 同步融合来源

在 `thirdhand_va.vision.preview` 中提供一个实现现有 `FrameSource` 接口的融合来源。它拥有
算法 MJPEG 来源和后台深度读取器，只返回帧号完全相同的融合帧；不会把旧深度叠到新
算法画面。来源断开时关闭自身资源并让现有预览服务执行有界重连。

该模块不拥有相机、不启动算法、不打开端口，可使用离线来源和假来源独立测试。

### 受限的只读 HTTP 服务

复用现有 `PreviewHttpServer` 和 `PreviewService`，但保持当前“默认只允许 loopback”行为
不变。只有调用方同时显式提供以下三项时，服务器才允许非 loopback 监听：

- 具体监听地址，例如 `192.168.58.68`，禁止使用 `0.0.0.0`；
- 允许的客户端网络 `192.168.58.0/24`；
- 至少 128 bit 的随机访问令牌。

服务只接受 `GET /stream.mjpg` 和 `GET /health`。两者都必须携带正确令牌；令牌使用
恒定时间比较。其他路径和所有非 GET 请求均被拒绝。服务不提供控制、选择、动作、文件
读取、目录浏览或跨域接口。

### 应用入口

新增独立入口 `python -m apps.vision_lan.main`，只负责组装融合来源、访问策略和 HTTP
生命周期。默认端口为 8770；启动时生成随机令牌，并在 Ubuntu 终端打印可直接复制到
Windows 的完整 URL。`Ctrl+C` 只停止该局域网查看进程，不影响端口 3000、8765、8766
或机器人服务。

同时提供 VS Code Remote-SSH 调试启动项。核心融合来源、访问策略和应用入口均可注入
离线来源或假服务，在不启动相机和现有系统的情况下设置断点和测试。

## 数据流

```text
127.0.0.1:3000 算法流 ─┐
                         ├─ 精确帧号同步 ─ 深度融合 ─ 只读 MJPEG :8770 ─ Windows 浏览器/VLC
127.0.0.1:3000 深度流 ─┘
```

端口 8770 只消费现有画面，不向端口 3000 发送控制请求。慢速 Windows 客户端最多保留
一个最新待发送帧，不能反向阻塞算法或相机。

## 故障行为

- 算法或深度源短暂断开：服务保持运行并重连，不输出伪造的同步画面。
- 深度帧号未匹配：显示带 `DEPTH WAITING` 标记的算法画面。
- Windows 客户端过慢：丢弃旧视频帧，只发送最新帧。
- 令牌错误或客户端不在允许网段：返回拒绝响应，不泄露画面。
- Ubuntu 地址变化或 8770 被占用：启动失败并打印明确原因，不回退到其他端口或
  `0.0.0.0`。
- 进程退出：释放自身 HTTP 连接和读取器，不停止任何上游服务。

## 测试与验收

- 单元测试：精确帧号融合、错误帧拒绝、来源关闭与重连、访问令牌、网段限制、请求方法
  和路径限制、慢客户端最新帧策略。
- 入口测试：默认端口 8770、禁止 `0.0.0.0`、随机令牌输出、无机器人控制能力。
- 集成测试：使用离线算法图和深度图生成一帧真实 MJPEG，在本机通过局域网地址读取并
  验证 JPEG、帧号和深度融合结果。
- 运行验收：启动前后记录 3000、8765、8766 的监听进程和 PID，确认保持不变；确认新增
  监听仅为 `192.168.58.68:8770`；Windows 在关闭 SSH 转发后仍能持续查看。

## 启动、关闭与回退

- 启动：在 Ubuntu 或 VS Code Remote-SSH 终端运行局域网查看入口，复制它打印的 URL
  到 Windows 浏览器。
- 关闭：在启动终端按 `Ctrl+C`。
- 回退：停止该独立进程即可完全回退；无需修改或重启已有相机、算法和控制服务。
